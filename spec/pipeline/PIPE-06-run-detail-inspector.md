# PIPE-06 — Run detail & event inspector

- **Status:** Draft
- **Epic:** pipeline
- **Estimate:** M
- **Depends on:** PIPE-05
- **Blocks:** PIPE-07, PIPE-10
- **TDR:** §23, §38, §42

## 1. Why

A live timeline is great while a run is going; after it finishes, users and
admins need to *understand* it: what was imported, what failed and why, which
artifact was produced, what parameters were used, and — for the developer — the
raw event/context trail. Today the `job-detail-sheet` shows a few meta rows and
a flat error table. This spec turns run detail into a proper inspector with
grouped issues, artifacts, parameters and a raw event/context viewer.

## 2. Scope

**In**

- Rework `components/data-processing/job-detail-sheet.tsx` into a tabbed
  inspector consistent with `PipelineRunResource` (Overview, Issues, Artifacts,
  Parameters, Advanced).
- The same tab set on the run page (`PIPE-05`) below/alongside the timeline.
- **Grouped issues**: server-side aggregation of import errors by
  `type + message` with counts and sample rows; "Download failed rows" wired to
  the existing import-report artifact.
- **Artifacts** tab: name, size, mime, created, expiry, download/preview.
- **Parameters** tab: entity, format, sanitized filters, input file, owner.
- **Advanced** tab (gated): pretty-printed raw event `context`, correlation id
  with copy, links to Audit/Telescope/Pulse when permitted.
- Paginated full event table for history beyond the timeline window.

**Out**

- The live timeline itself (PIPE-05).
- Retry/resume flows (PIPE-07).
- Retention of events (PIPE-12).

## 3. Data model

- No new tables.
- `PipelineEventResource` already carries `context`; ensure it is bounded
  (truncate very large payloads with a `truncated: true` flag).

## 4. Backend

- **Issues aggregation:** add `DataProcessingJobService::issuesSummary(job)` (or
  a dedicated `PipelineIssueAggregator`) that reads `errors` (and/or
  `pipeline_events` of level error/warning) and returns capped groups:
  `{ type, message, count, sample_rows[], first_seen, last_seen }` (top 50).
  Reads via the repository.
- Include `issues_summary` (or an `issues` key) in `PipelineRunResource`.
- **Artifacts:** reuse `artifactList()`; expose `size`, `mime`, `expires_at`,
  `download_url`.
- **Advanced:** expose `correlation_id` (from the audit context / job row) and
  raw `context` only when the viewer has `data-processing.manage` (or
  `developer.view`); otherwise omit from the resource (never send secrets).
- **Events endpoint:** support a paginated **table** mode of events via the
  existing `activity.show` route (`?page=` with `only: ['events','eventsMeta']`)
  or reuse `after/before_sequence`. Prefer adding an explicit
  `GET /activity/{job}/events` Resource collection for table pagination and
  infinite scroll, gated by `DataProcessingJobPolicy::view` (JSON endpoint
  returning `PipelineEventResource::collection` is allowed by the frontend
  rules).
- Keep controllers thin; logic in services/repositories.

## 5. Frontend / UI

**Sheet (quick peek)** — `job-detail-sheet.tsx`:

- Header: type/entity tile, name, status badge, stage, relative created time,
  and an **"Open full run"** link to `activity.show`.
- `Tabs`: **Overview** (compact progress + timing + counts + stages),
  **Issues** (grouped table, only when `error_count > 0`),
  **Artifacts**, **Parameters**. Advanced is hidden in the sheet; it lives on
  the full page.

**Run page tabs** — on `pages/data-processing/show.tsx`:

- The timeline is the default tab; add sibling tabs for **Issues**,
  **Artifacts**, **Parameters**, **Advanced**.
- Tabs are URL-addressable (`?tab=issues`) so links are shareable.

**Issues tab**

- Table of issue groups: count badge, type badge, message, first/last seen,
  expandable to show sample rows (`row`, `message`).
- Header action: **Download failed rows** (existing import report).
- Empty state: "No issues — every row imported cleanly."

**Artifacts tab**

- Card list: file icon by mime, name, size (`formatBytes`), created relative
  time, expiry ("expires in 5 days"), Download button, and Preview for
  previewable types (reuse `file-preview-dialog`).
- If none: "No files were generated by this run."

**Parameters tab**

- Definition list of entity, format, filters (as chips), input file (with
  size), owner, and a **Duplicate with these parameters** action (PIPE-07).

**Advanced tab** (gated)

- Correlation id with copy button.
- Event table: paginated, columns time/type/level/stage/message/duration, row
  click expands pretty JSON `context`.
- Raw job JSON (readonly code block with copy).
- Links to Audit log (`?correlation_id=`), Telescope, Pulse when the user has
  access.

**Event inspector specifics**

- Pretty JSON viewer with syntax colouring (lightweight, no heavy dep), copy,
  and a "redacted" note when `truncated`/`redacted` flags are present.
- Never render a value that the backend omitted for permission reasons.

### States

- Loading skeletons per tab.
- Permission-denied tab: hidden entirely rather than disabled-with-error.
- Expired artifact: show disabled download + "expired" note.

### A11y & i18n

- Tabs use the shadcn `Tabs` primitive with proper `aria-controls`/roles.
- Code/json blocks are `<pre>` with `tabIndex=0` for keyboard scrolling; copy
  button announces success via a polite live region.
- All labels/empty texts added to the five `lang/app/*.json`.

## 6. API / routes / props

- `GET /activity/{job}` (`activity.show`) props add `issues`, `artifacts`,
  `parameters` and (gated) `advanced`.
- `GET /activity/{job}/events` (`activity.events`) → paginated
  `PipelineEventResource::collection` for the Advanced table.
- Tabs via `?tab=`.

## 7. Acceptance criteria

- [ ] The sheet and run page share one tabbed inspector component.
- [ ] Issue groups aggregate duplicates with counts and sample rows.
- [ ] Failed rows can be downloaded when an import report exists.
- [ ] Artifacts show size, expiry, download and (where possible) preview.
- [ ] Advanced tab and raw context are only available to authorized users.
- [ ] Event table paginates and expands context.
- [ ] `composer check` passes.

## 8. Tests

- **Feature** `tests/Feature/Pipeline/RunInspectorTest.php`:
  - issues summary for a failed import matches the seeded errors (grouping +
    counts);
  - `activity.events` paginates and is forbidden without permission;
  - advanced fields absent for a normal viewer and present for a manager;
  - expired artifact is reported as non-downloadable.
- **Unit:** `PipelineIssueAggregatorTest` for grouping/capping/sample selection.

## 9. Notes & open questions

- Decide whether grouping uses `errors` JSON (already stored) or event context;
  recommendation: `errors` for imports, events for sync runs, unified by the
  aggregator.
- Syntax highlighting for JSON: keep dependency-free (CSS classes) or a tiny
  library; decide during implementation (bundle budget).
